## 📊 Workflow

### Полный цикл работы с ивентом:

1. **Организация создает ивент**
   - Заполняет форму в 6 шагов
   - Нажимает "Опубликовать"
   - Ивент сохраняется в БД

2. **Волонтер видит ивент**
   - На главной странице
   - В каталоге с фильтрами

3. **Волонтер подает заявку**
   - Нажимает "Подать заявку"
   - Заявка создается со статусом "pending"

4. **Организация управляет заявками**
   - Переходит в "История" → выбирает ивент
   - Видит список заявок с данными волонтеров
   - Нажимает "Принять" или "Отклонить"

5. **Система отправляет уведомления**
   - Email на почту волонтера
   - Обновление статуса в приложении
   - Изменение цвета индикатора

6. **Волонтер получает уведомление**
   - Видит изменение статуса в "Мои заявки"
   - Получает email с подробностями

## 🔧 Технические детали

### База данных
- **PostgreSQL 15**
- Таблицы: users, profiles, organization_profiles, events, applications
- Foreign keys с CASCADE delete
- Индексы на email, user_id, event_id

### Безопасность
- JWT токены для аутентификации
- Bcrypt для хеширования паролей
- Валидация данных через Pydantic
- Защита от SQL injection (SQLAlchemy ORM)

### Performance
- Eager loading для relationships
- Индексы на часто запрашиваемые поля
- Кеширование токенов в SharedPreferences
